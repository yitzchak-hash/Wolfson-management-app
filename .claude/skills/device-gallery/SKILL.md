# The Device Gallery

The owner reviews all UI work through ONE artifact page of real screenshots
of the running app — the exact code on the working branch — framed per
device. `docs/DEVICE-GALLERY-PROMPT.md` is the portable statement of the
method; this skill is how it runs in THIS repo.

## The standing rules

- **One link, forever.** Republish the SAME artifact file path (and pass the
  stored `url` when this session didn't create it — find it with the
  Artifact tool's `list` action; the page is titled "Device Gallery",
  favicon 🖼️). Never mint a second gallery.
- **Real screenshots only** — captured from the app served by the dev
  server, on the current branch, with realistic seeded data. Never mockups.
- **Refresh after every UI change**, before reporting it done. The page
  must never be older than the code being discussed.
- **Screenshots show; the audit proves.** Run `scratchpad/shots.mjs` at any
  size a change could affect (`W`/`H`/`VIEW=landscape` env vars) — overflow
  and clipped counts must be 0.

## Making the pictures

`node scratchpad/gallery.mjs [profile…]` captures every profile (or just
the named ones) to `scratchpad/gal-<profile>-<screen>.png`: the drawer WITH
a real plan (a pdf-lib sheet served on `/api/drive-fetch`), the diagram,
the board (switched through the real header dropdown), and the worker
portal with a task open. Profiles: iphone · galaxy · flip · fold-open ·
fold-side · fold-big · ipad-port · ipad-land · ipadpro11 · ipadpro13 · pc.
Needs the dev server on 5173 and `npm i --no-save playwright pdf-lib` in a
fresh container. Seeding rides `scratchpad/seed.mjs` (clock-relative dates,
a worker with map permissions — do not regress either).

## Building and publishing the page

The gallery HTML is generated by a builder script (session scratchpad; the
structure matters more than the file): a small shell document whose BODY
MARKUP lives once inside `<script type="text/x-page" id="page-src">`, the
pins inside `<script type="application/json" id="pin-data">`, and a loader
script that renders the body from #page-src and the pins from #pin-data.
That structure is what lets the page republish ITSELF without duplicating
10&nbsp;MB of images: its publish routine reassembles the document from the
shell constant + the two script blocks' text — never by serializing the
live DOM. The artifact declares `capabilities: {artifact: {}}`; keep
declaring it on every republish from the tool side too.

## The pin-notes loop

1. The owner presses "Note a change" on the page, taps a spot on a
   screenshot, types or dictates (SpeechRecognition where the browser has
   it), and presses "Send to Claude" — the page publishes a new version of
   itself with the pins in `#pin-data`. Each pin: `{device, screen, x, y,
   text, at, done}` (x/y in % of the screenshot).
2. When the owner says to check his notes: READ the artifact (Artifact tool
   `action: "read"` with its URL — an owner's artifact returns raw HTML;
   remote sessions get no automatic wake, so he tells us), parse
   `#pin-data`, and treat every pin with `done: false` as a change request
   anchored to that device/screen/spot.
3. Make the changes, re-run the audit, re-capture the affected profiles,
   rebuild the page — carrying the pins forward with `done: true` and a
   one-line note of what was done — and republish to the same URL. Drop
   done pins on the FOLLOWING round, so he gets one round to check them.
4. Never delete a pin that wasn't acted on; never answer "what should I
   change?" without reading the pins first.

## Traps already paid for

- The pins must survive the page's own republish-reload: the page stashes
  unsent pins in `sessionStorage` before `publish()` (the conflict rule).
- User text goes into the JSON block with every left angle bracket escaped
  as its JSON unicode escape (backslash-u003c), or a note containing a
  closing script tag breaks the document it is embedded in.
- After the page publishes itself, the local HTML file in any session is
  BEHIND the artifact — re-read and merge before republishing from the
  tool, or the owner's pins are silently clobbered.
