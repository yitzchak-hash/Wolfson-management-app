# TzviAir Plan Sketcher — MASTER PLAN

Sealed 2026-09-01 through the slow-plan method: 7 sittings, 40 locked picks,
answered by the owner on the interactive plan page ("The Plan Sketcher
Blueprint" artifact). **Where any older note disagrees with this file, this
file wins; older records are kept as history, never rewritten.**

## What it is (the owner's own frame)

A simple framework: sketch plans easily, save them, send them to customers.
Its own app, its own repo, its own website — connected to the management app
the way Google Sheets is connected to Drive. The only integration is copying
the consolidated markup code back into the Wolfson management app at the end.

## The 40 picks

4. **Version 1 has no login** — open link, like the TV wall. Workspace

5. **The pilot: the Levi villa** — four floors, already cleaned from scans.
6. **Own repo, markup code copied in — AT THE END** (sharpened by pick 33):
   the owner is still improving the markup studio in the management app, so
   the copy is taken when this planning is done, freshest code wins. At the
   very end, the consolidated markup code is brought back into the
   management app's studio.
7. **Mark up stays untouched** — the management app's drawer gains a
   "Build plan" door that opens the Sketcher on that job. The existing
   markup studio is never modified by this project.
8. **Same Firebase + Drive** as the management app — one truth: same jobs,
   same folders.
9. **The office computer converts DWGs** — a small TzviAir converter helper

   future universal worker driver ("the base"). A $5–10/mo cloud machine is
   the recorded fallback if the office PC proves unreliable.
10. **Free Vercel address for now** — tzviair-plan-sketcher.vercel.app; a

### The clean-plan room (sitting 2)
11. **Clean is automatic first, easy to adjust** — the clean base appears by
    itself; a checklist flips anything the AI got wrong. Full multi-floor
    support with a floor switcher.
12. **Controls speak plain words** — Walls · Doors & windows · Furniture ·
    Measurements…; the AI maps raw layer names ("cbcvb") behind the curtain.
13. **Scan cleaning is layered: automatic → three dials → full eraser.**
    Rely on the automatic; dials (remove colors / remove stains / crop) for
    stubborn scans; the markup studio's erasers can rub out plan content.
    Safe because the clean base is its own saved copy — the architect's
    original file is never touched.
14. **Sizing is automatic — the plan explains itself.** The Sketcher reads
    the written measurements, floor names and title-block information,
    sizes the plan and builds a sidebar of the job's plans with details
    filled in. Two-tap calibration is the check and the fallback for
    unreadable scans. ("2 is 2.")
15. **The clean base saves to the job's Drive folder + the database** —
    cleaned once, ever.
16. **A multi-floor file is framed into one plan per floor** (AI proposes
    the frames). At export: the whole job as ONE PDF or separate PDFs.

### The block catalog (sitting 3)
17. **Shelves by category with search** — pictures at a glance, the
    widget-store manner.
18. **Drag one, stamp many** — drag from the shelf for a single piece;
    stamp mode for repeated placements.
19. **Blocks are locked at true size, with a tiny padlock** (the job-board
    lock idiom) that deliberately unlocks ratio/resize. **Grills stretch
    along their LENGTH** (one-axis pull, not aspect ratio). Which grills
    behave how is settled when the real blocks arrive (open follow-up).
20. **The catalog waits for the architects' master file** — their official
    ~100-block DWG IS the catalog; no harvested stand-in.
21. **Fixed catalog + a PNG door** — anyone can add a PNG into a category;
    name required, and real cm required (a picture carries no scale).
22. **Every placed block knows what it is** — name, model, size, note on a
    small card; the plan can count itself (seed of the bill of quantities).

### The gvs (sitting 4)
23. **Gvs drawing has TWO modes** — corner-to-corner tracing that snaps to
    walls AND rectangle-drag, both on the toolbar.
24. **The shape knows its numbers live** (m², running meters, drop height) —
    with the architect's real running-meter formula to be slotted in when
    the owner gets it explained (open follow-up). **The block-rules page**:
    a settings screen listing every imported block, each carrying rules
    (e.g. minimum drywall height) so placing it in a gvs auto-adjusts the
    gvs.
25. **Units and grills place free** — nothing is glued to a gvs; counting
    comes from the block cards and shapes, not grouping.
26. **Soft amber warnings, never blocks** — the app advises, the
    professional decides.
27. **Named options per floor** — Option A / Option B duplicated at one
    press; exports say which.
28. **Pipes: draw rough, get straight** — color the path with a pen and the
    app straightens it into a clean run following where the hand went, true
    meters written on it; no raw hand-marks on the plan.

### Output (sitting 5)
29. **The exported sheet copies the architects' OWN sheet** — the owner will
    hand over a real plan PDF; the export copies its right-side column
    exactly (format, fonts, everything). Open follow-up: that PDF.
30. **No separate numbers page** — the numbers show on the sheet's side the
    way the architects' plans already do. Plus: **export to Excel/CSV** — a
    list of the units and the full bill of quantities.
31. **Export asks each time** — Drive, download, or both.
32. **The quote stays separate — until the CRM.** When the CRM rebuild
    redoes proposal-making, this whole system plugs into it. Not v1's job.
33. **Saving & versions: the management app's system, verbatim.** The
    saving/versioning is already built and recently improved; nothing new is
    invented. At the end that exact code is copied, a home screen is added,
    and it becomes its own app.
34. **The worker portal is untouched** — exports don't feed it ("currently
    unrelated"). The Sketcher sketches, saves, and sends to customers.

### Devices & people (sitting 6)
35. **PC first, iPad right behind** — every screen gets the responsive
    layout from day one; planning gestures are tuned for mouse and
    finger-on-tablet first.
36. **The home screen**: job cards from the shared Firebase + a settings

37. **English by default, Hebrew available** (the copied bilingual machinery

38. **Anyone in the company who needs the link gets it.**
39. **The Sketcher gets its own Device Gallery** — the same screenshots +

### The seal (sitting 7)
40. **Picking the right file from the job's main folder** (answers the
    owner's question in pick 36's note): the Drive search opens the job's
    folder and lists every VIEWABLE file (PDF / image / DWG — the

### Sitting 8 — the hand (locked 2026-09-02)
41. **The catalog is an always-open shelf down one side** while you work
    (refines 17). ~120px of width; you learn where each block sits.
42. **Letting go snaps the block to the nearest wall, turned to face the
    room**; dropped in the middle of a room it stays exactly where it was
    put — nothing is forced.
43. **Turning is a round handle above the block, snapping every 15°**;
    Shift frees the angle; works with a finger on the iPad.
44. **Callout labels draw themselves with every block and are dragged to
    move** (the text comes from the block itself — pick 22 — so it can never
    disagree with what is placed). Owner refinement, in his words: *"but also
    an option to move the text and some more control"* → a selected label
    gets a small toolbar (flip side · edit text · hide); how much further
    that control goes is pick 49.
45. **Unit letters are automatic per model, in placement order, and
    renumberable** (a right-click / the card renumbers). Owner refinement:
    *"we need a way to do 2 or 3 systems so A1,2,3,4 and then B1,2,3,4"* →
    a SYSTEM row (A · B · + system); the lit system letters the next unit;
    a unit's card moves it between systems and the rest renumber. How a
    system is defined is pick 48.
46. **Stamping is tap, tap, tap until Escape** (refines 18): the block stays
    on the cursor and every tap leaves one.

## What was proven before sealing (in the planning container, on real files)

- **DWG door**: ODA File Converter 27.1 converts the architects' real DWGs
  losslessly (headless via xvfb); ezdxf parses them ($INSUNITS=5, real cm);
  the ezdxf drawing frontend silently drops virtual entities, so the clean
  render is a ~150-line direct geometry→SVG renderer
  (`prototypes/render_direct.py`) — it produced the clean layout+furniture
  image the owner approved.
- **PDF door**: the architects' plotted PDFs carry real OCG layers; pymupdf
  toggles them via `set_layer_ui_config` (not `set_layer`).
- **Scan door**: `prototypes/cleanscan2.py` cleaned all four Levi-villa
  floors by color/shape (HSV strip, ghost wipe, small-blob removal, crop).
- LibreDWG is NOT production-grade for these files (dangling inserts,
  mirrored Hebrew); ODA is the converter. ODA is a native binary → cannot
  run on Vercel functions → pick 9's office-PC helper.
